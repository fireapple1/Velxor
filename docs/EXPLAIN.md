# Velxor — 쉽게 풀어 보기

> Linux 컴퓨터에 깔린 **랜섬웨어를 실시간으로 잡는 PoC**.
> 기존 안티바이러스가 "**파일 시그너처**"로 잡는다면, Velxor 는 "**행동**"으로 잡는다.

---

## 1. 랜섬웨어가 뭔데?

```
사용자 파일 (사진/문서/PDF)
     ↓ 악성코드 실행
     ↓
[랜섬웨어가 1초 안에 수백 개 파일을 암호화]
     ↓
사용자 파일이 모두 .crypted / .locked 같은 확장자로 바뀜
     ↓
"비트코인 1개 송금하면 풀어드림" 협박장
```

피해의 핵심은 **속도**다. 사용자가 마우스로 무언가 이상하다는 걸 느꼈을 때는 이미 늦었다.

---

## 2. 기존 백신은 왜 못 잡나?

| 방식 | 한계 |
|---|---|
| **시그너처 기반** (파일 내용 hash 비교) | 새 변종 1초만 컴파일해도 통과. 변형이 쉬움. |
| **클라우드 평판 DB** | 신상 랜섬웨어는 DB 등록 전 |
| **휴리스틱** | 오탐 너무 많아서 실제 적용 어려움 |

→ **사후 대응**(`이미 암호화된 다음에 알림`) 으로 끝남.

---

## 3. Velxor 의 접근

> "**파일 내용**을 보지 말고, **프로세스의 행동 패턴**을 보자."

랜섬웨어는 정상 프로그램과 **행동**이 다르다.

| 정상 워크로드 | 랜섬웨어 |
|---|---|
| `rsync` 백업: 작은 dummy 파일 다수 복사 (~8 byte) | 사용자 파일 (4KB~256KB) 를 random byte 로 덮어쓰기 |
| `tar` 압축 해제: 다양한 확장자 (.js, .json, .md…) | 단일 확장자로 모두 변환 (.crypted) |
| `git clone`: 시간에 분산된 쓰기 | **1초 안에 수백 개 동시 rename + write** ⚠ |

이 **"1초 안에 수백 개 rename + write"** 가 결정적 차이다.

## 4. 4단계 파이프라인

```
┌─────────────────────────────────────────────────────────┐
│  [1] Rust fanotify collector                            │
│      커널 fanotify subsystem 에서 파일 시스템 이벤트 수신 │
│      "PID 1234 가 /home/user/sales.docx 를 rename 했다"  │
└──────────────────┬──────────────────────────────────────┘
                   │ JSON event stream (mpsc channel)
                   ↓
┌─────────────────────────────────────────────────────────┐
│  [2] Rust 집계 서비스                                    │
│      1초 sliding window 로 PID 별 묶기                   │
│      "PID 1234: 1초 안에 487 file rename + 487 write"    │
└──────────────────┬──────────────────────────────────────┘
                   │ HTTP POST /classify { events: [...] }
                   ↓
┌─────────────────────────────────────────────────────────┐
│  [3] Python 분석 엔진 (Flask)                            │
│      6개 피처 → Logistic Regression                      │
│      write_rate=487/s, ext_diversity=2, size_mean=130KB  │
│      → ransomware probability 0.96                      │
└──────────────────┬──────────────────────────────────────┘
                   │ verdict: "ransomware"
                   ↓
┌─────────────────────────────────────────────────────────┐
│  [4] 자동 차단 + UI 알림                                  │
│      SIGTERM → 200ms 대기 → SIGKILL                      │
│      Electron UI: 노드가 빨갛게 깜빡 + 차단 배너          │
└─────────────────────────────────────────────────────────┘

전체 소요: 50ms ~ 100ms (1초 window 끝나면 즉시 판정 + 차단)
```

---

## 5. 6개 피처 (모델이 보는 것)

| 피처 | 의미 | 랜섬웨어 특징 |
|---|---|---|
| `write_rate` | 1초당 write 횟수 | 매우 높음 (수백/s) |
| `rename_rate` | 1초당 rename 횟수 | write 와 거의 1:1 |
| `ext_diversity` | 확장자 종류 | 작음 (보통 2개: 원본 + .crypted) |
| `size_mean` | 평균 파일 크기 | 사용자 문서 (수십 KB) |
| `size_std` | 파일 크기 분산 | 비교적 균질 |
| `pid_fanout` | 활동 PID 수 | 1 (단일 악성 프로세스) |

## 6. 성능 (합성 PoC 기준)

- 탐지율: **30/30** (held-out 변종 v3, .pdf → .locked)
- 오탐: **0/40** (rsync/unzip/git/npm 합법 워크로드)
- 분류 latency: **6 ms** (< 100 ms 목표)
- 1시간 sustained run: 메모리 누수 0 %
- 자동 차단 시간: < 1 s (감지 → SIGTERM → SIGKILL)

---

## 7. 솔직한 한계 (학교/공모전 PoC)

- 학습 데이터가 **합성** — 실제 랜섬웨어 패밀리 일반화 안 됨
- 8 KB 이상의 균일한 binary write burst (`dd`, `tar`, 사진 백업) 는 **오탐 위험**
- 운영 배포 시 fanotify 실 trace 캡처 + entropy 피처 + RandomForest 필요
- 시연 영상 (`docs/demo/ac3-demo.mp4`) 은 stub 모드 — 실 ML 분류기 우회

자세한 한계 분석은 [`docs/AC5-results.md`](./AC5-results.md) §4 참조.

## 8. 한 줄로 다시

> **"기존 백신이 '얼굴 사진'으로 사람을 알아본다면, Velxor 는 '걷는 모양'으로 알아본다."**
> 사진은 바꿀 수 있어도 걸음걸이는 못 바꿈 → 새로운 변종도 잡힘. 단, 비슷한 걸음걸이의 정상 사람(8KB+ 백업)을 오인할 위험 있음.
