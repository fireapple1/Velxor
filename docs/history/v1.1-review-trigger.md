## A 자체 노트 (v1.1에 미리 반영할 후보)

A 본인 영역에서 v1-draft 발행 후 발견한 부족점. Week 3 collation 시 B/C 노트와 함께 통합 예정.

1. `BehaviorEventV1.op_detail`의 `FileWrite` 외 variant 미정의 (§1.2)
   - 현재: `FileWrite`만 `{file_size, entropy_hint}` 명시
   - 제안 (additive): `FileRename`은 `{src_path, dst_path}`, `ProcessCreate`는 `{argv, cwd}` 추가 (모두 optional)

2. `BehaviorEventV1.dropped_since_last` u32 max 포화 시 동작 미정 (§1.4)
   - 현재: "다음 successful send에 동봉 후 0 리셋"은 있으나 카운터가 2^32-1에 도달하면 어떻게 되는지 없음
   - 제안 (additive): 카운터는 saturating add (포화 후 더 이상 증가 안 함), payload 동봉 시 `dropped_saturated: bool` optional 필드로 신호

3. `POST /classify` 에러 응답 shape 미정 (§2.2)
   - 현재: 200 OK + verdict만 명시
   - 제안 (additive): 비-200 응답에서 `{error: string, retry_after_ms?: u32}` (A의 reqwest timeout 200ms 분리와 별개로, C 모델 실패 시 fallback rules로 갈지 verdict 미발행할지 결정 필요)

4. `image_path` readlink 실패 시 fallback 미정 (§1.2)
   - 현재: `image_path: string` 필수
   - 제안 (additive): PID race로 `/proc/<pid>/exe` readlink 실패 시 `image_path: "<unknown:pid=N>"` 형태 sentinel, 별도 `image_path_resolved: bool` (default true) 추가
